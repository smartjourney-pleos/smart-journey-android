# 프론트엔드 보완 검증 - 2026-11-12

> 개정 기획(v4) 이전 화면에 대한 검증 기록이다. 이 브랜치의 화면 코드(`Screens.kt`·`Components.kt`)는 0.2.x 화면 재구성으로 대체돼 main 병합 때 반영하지 않고 현재 구현을 유지했다. 문서와 캡처만 기록으로 남긴다. 현재 검증은 [0.2.9 검증 기록](release-0.2.9.md)을 본다.

현재 `dev` 작업 폴더에서 Codex와 Claude가 파일을 나누어 수정했다. 현재 구현을 기준으로 준비·진행·동의·주행 제한 화면을 보완했으며, 다른 작업 공간의 음성 전용 흐름을 통합한 작업은 아니다.

## 변경 범위

- `ui/Components.kt`: 큰 버튼의 로딩·클릭 차단·접근성 상태 안내, 작은 지표 폭에서 숫자 크기 조절.
- `ui/Screens.kt`: 주행 제한 우선 분기, 여정 시작 비활성 사유와 로딩 연결, 방문 순서 안내, 데모 데이터 고지, 센서 추정 문구, 동의 목적·거부 결과·철회 위치, 좁은 창 지표·헤더·주행 안내 배치.
- 여정 엔진·차량/내비 연동·알림 서비스 동작은 변경하지 않았다. 실제 매장 접수·음성 승인·QR 화면을 추가하지 않았다.
- PR에는 기반 `dev`의 미푸시 커밋 5개(Pleos 가이드 반영, SDK/POI·내비 화면 전환, 디자인 시스템, 통합, 여정 상태 저장·복원)가 함께 포함된다. 이 기반 변경과 이번 UI 보완을 커밋 단위로 구분한다.
- 기존 작업 중이던 `WaitingBackend.kt`, `scripts/demo-flow.sh`, `scripts/record-demo.sh` 변경은 이 작업에서 수정하지 않았고 PR의 스테이징·커밋에서 제외했다.

## 빌드·정적 검증

Claude 실행 보고와 생성된 로컬 테스트·린트 보고서를 확인했다.

| 검증 | 결과 |
| --- | --- |
| `:app:assembleDebug` | 성공 |
| `:app:assembleRelease` | 성공, 서명되지 않은 APK |
| `:app:testDebugUnitTest` | 30개, 실패 0, 오류 0 |
| `:app:lintDebug` | 오류 0. 기존 경고는 남아 있음 |
| `git diff --check` | 통과 |

최초 화면 보완 뒤 단위 테스트 30개를 통과했고 후속 문구·헤더 변경 뒤 빌드·린트를 통과했다. PR 준비 시에는 원본 작업 폴더의 다른 변경을 제외한 별도 작업 트리에서 `:app:assembleDebug :app:assembleRelease :app:testDebugUnitTest :app:lintDebug`를 다시 실행해 모두 통과했다(30개, 실패·오류 0, 린트 오류 0).

APK는 `app/build/outputs/apk/debug/app-debug.apk`, `app/build/outputs/apk/release/app-release-unsigned.apk`에 생성된다. 배포·업로드는 하지 않았다.

## 에뮬레이터 확인

Codex가 시작 전 실행 중인 adb 기기가 없는 것을 확인하고, 전용 AVD `SmartJourney_Design_QA`를 `emulator-5580`으로 실행했다. 다른 세션의 기기는 조작하지 않았다. 검증 후 야간 모드를 `sensor`로 되돌리고 이 QA 에뮬레이터만 종료했다.

- 미동의 + 주행 제한에서 동의 버튼 대신 잠금 안내가 표시됨을 확인했다.
- 주간의 넓은 준비 화면에서 실제 코드의 매장명·방문 순서·시작 비활성 사유·데모 고지를 확인했다.
- 829dp 및 600dp 창에서 진행 지표의 가로·세로 배치를 확인했다.
- 최종 APK의 600dp 야간 주행 화면에서 앱명·부제와 규제 배지가 분리되고, 상태 문장이 어절 중간에서 잘리지 않는 것을 확인했다.
- 시나리오 신호는 debug 전용 `DemoReceiver`로 주입했다. 터치 버튼을 모두 직접 누르는 전체 사용성 테스트는 아니다.
- 초기 빌드에서 데모 등록·하차 3/4명 확인 로그를 관찰했다. 캡처 당시 원본 작업본의 매장 표시명 수정은 PR에 포함하지 않아 PR 코드의 데모 매장명(42dot·소프트웨어드림센터)과 캡처의 이름은 다르다. 실제 차량 센서 변화나 외부 매장 수신 검증은 아니다.

빠른 `am task resize`와 주야간 전환 직후 일부 캡처에 헤더·시스템 영역이 부분적으로 미갱신되는 현상이 관찰됐다. 후속 재캡처에서는 다시 표시되었지만 원인을 앱 또는 에뮬레이터로 확정하지 않았다. 모든 전환의 시각 품질, 실제 마이크·실차·공식 매장 연동은 검증하지 않았다. 로딩 스피너·실패 화면은 이번 기기에서 강제로 유지·재현하지 않았으며 코드와 빌드로 확인했다.
