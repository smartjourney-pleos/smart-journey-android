# 0.2.9 release 검증 기록 — 2026-11-12

대상: 서명된 release APK 0.2.9(versionCode 11), SHA-256 `aacfa832cd8e5ac40923c5984861ff4dc40be226cc7cd9c995bc235b88a23927`. APK 안의 `assets/schema.json` version은 0.2.9이고, 서명 인증서는 `CN=Smart Journey, O=smartjourney-pleos, C=KR`이다.

## 0.2.9에서 고친 것

- 0.2.8 독립 QA에서 실패한 경우: 방문을 시작하고 내비가 앞으로 나온 뒤 5초쯤 지나 순정 내비에서 "안내 종료"를 누르면, 내비는 종료됐는데 앱에는 "진행 중 · 요청 전" 카드가 남았다. 경로 설정이 끝난 지 약 1초 만에 온 `onRouteCancelled`를 "우리 경로 요청 직후 3초" 구간이라는 이유로 무시했기 때문이다.
- 지금은 취소 이벤트가 오면 우리 경로 요청이 끝날 때까지 기다린 뒤, `getRouteStateInfo()`로 안내 중인 경로가 있는지 묻는다(`core/RouteCancelFilter.kt`).
  - 경로가 없으면 운전자의 안내 종료로 보고 접수 전 방문을 닫는다.
  - 경로가 있으면 이전 경로를 우리 경로로 바꾸면서 생긴 취소로 보고 무시한다.
  - 3초 기준은 내비가 2초 안에 답하지 않을 때만 쓴다.
- 에뮬레이터 내비는 안내 중에도 `isRouting=false`를 보냈다. `naviMode`는 안내 중일 때 `ROUTE_GUIDING`, 안내 종료 뒤에는 `SAFE_GUIDING`이었다. 그래서 `isRouting || naviMode ∈ {ROUTE_GUIDING, SIMULATION_GUIDING}`이면 안내 중으로 본다. 실차 값은 확인하지 못했다.
- 새 경로 요청이 시작되면 이전 요청 때 받은 취소의 상태 조회와 보관 작업을 모두 취소한다. 이전 요청의 늦은 응답이 새 방문을 닫지 않는다.
- `assets/schema.json` version을 앱 버전과 맞추고, 두 값이 다르면 실패하는 테스트를 추가했다.

- **강제 권한 없는 일반 설치**(오버레이 권한 기본값, 별도 AVD, user 10):

- **권한을 따로 부여한 QA 환경**(일반 사용자 경로가 아님. 검증 뒤 권한을 기본값으로 되돌림):

## 미해결 (이번 검증 범위 밖)

- **일반 사용자 권한 경로의 지도 위 카드.** 이 Pleos 이미지에는 "다른 앱 위에 표시" 권한 설정 화면이 없다. 백그라운드 Activity 시작, fullScreenIntent, 알림 배너도 막혀 있다. 그래서 권한을 강제로 주지 않은 설치에서는 지도 위 카드가 뜨지 않고, 음성 질문이 기본 경로다. 위 카드 검증은 이 문제를 해결한 것이 아니다.
- **Gleo 실제 마이크.** 사람이 말하는 Gleo 호출과 승인 확인값 전달까지의 전체 흐름은 실행하지 못했다.
- **순정 내비 종료 전 확인.** 순정 내비의 안내 종료를 가로채 확인창을 띄울 공개 SDK 이벤트는 확인되지 않았다. 사전 확인은 우리 앱의 "방문 끝내기"에서만 한다. 순정 내비가 이미 끝난 뒤에는 경로를 자동으로 되살리거나 웨이팅을 취소하지 않는다.
- 실차 내비의 `naviMode`/`isRouting` 값, 공식 FormFactorConsole 검증은 하지 않았다.
- `v0.2.8-submission1` 태그(1차 제출)에는 이 수정 전의 중간 판정 코드가 들어 있다. 공개 태그는 옮기지 않았고, 0.2.9 수정은 main의 새 커밋으로 반영했다.
